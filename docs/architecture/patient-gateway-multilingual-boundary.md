# Patient gateway multilingual boundary

## Scope

This lock extends the existing `en-IN`, `hi-IN`, and `gu-IN` presentation preference into the authenticated patient gateway. It is intentionally limited to authority-neutral interface copy and navigation labels.

## Permanent invariants

- Locale is presentation state only. It must never choose or alter patient/physiotherapist persona, PAT/PHY identity, authorization, clinical linkage, appointment authority, invoice/payment authority, or financial calculations.
- The public PAT identifier is displayed byte-for-byte from the authenticated patient identity boundary. It is never translated, reformatted, inferred, or regenerated by the locale layer.
- Clinical facts, clinician-authored notes, invoice/reimbursement evidence, payment destinations, database state values, and provider identifiers are not automatically translated by this slice.
- Locale loading failure falls back to `en-IN` and must not block patient identity resolution, sign-out, or navigation.
- Translation catalogs are static application presentation resources. They do not become a source of database authority.
- Existing route/persona guards remain authoritative; localized labels cannot expose a route to a persona that the database/application boundary does not already authorize.

## Acceptance notes

The patient gateway now obtains the authenticated user's saved locale through the existing locale preference boundary and translates only gateway headings, explanatory copy, accessibility labels, sign-out state, and navigation labels. The PAT value itself remains untouched.

No schema, RLS, RPC, grant, clinical, financial, appointment, or payment contract changes are required for this slice. Therefore no database migration is justified.
